# 架构与关键决策

这份文档最值钱的不是结构图，是**「为什么这么设计」**。里面的取舍一年后自己也会忘，但它决定了还能不能放心改。

## 模块划分

```
watermark.pyw       界面层（CustomTkinter）。只管交互、预览、导出调度，不碰像素算法。
watermark_core.py   图像核心。纯函数，无 GUI 依赖，可单独 import 测试。
watermark_store.py  配置与日志。按文件夹读写 settings.json；写 logs/app.log。
```

分层的意义：核心能脱离界面测（写测试时不用起窗口），界面改动不会波及算法。

## 关键决策

### 1. 所有尺寸都用比例，锚在「图片较短边」

`size_pct`、`margin_pct` 按图片**较短边**的百分比算；描边宽度、底板各尺寸按**标志高度**的比例算。

原因：一批图的分辨率、横竖比例、方向都不一样。用绝对像素会让大图上的水印小得看不见、小图上又糊满整幅。锚在较短边之后，竖图和横图、4K 和 800px 出来观感一致。

### 2. 标志拆成「校徽」和「文字」两部分

`split_logo()` 按最宽的内部空白把标志切两半。深色底时**只给校徽垫圆底、只把文字反白**，而不是整块反白。

原因：校徽有具体图形和颜色，反白会毁掉它；文字是纯色块，反白最干净。这是用户提出的方案，比整块处理精致。

### 3. 标志在**目标尺寸**上组装，不先大盘再缩

早期写法是在标志原始分辨率（约 2760px）上做描边，再缩到实际尺寸（约 220px）。后果有两个：
- **描边宽度错**：在大图上描 30px、再缩到 1/12，实际只剩不到 3px
- **慢**：每拖一格滑杆都要在上百万像素上跑形态学膨胀

现在先把标志缩到目标尺寸、再在其上做描边（`build_mark(target_w, target_h)`）。

**连带决策**：`ImageDraw` 画圆/描边**不带抗锯齿**，直接在小尺寸上画边缘会毛。所以**小尺寸（长边 < 700px）时超采样 2 倍再缩回**；大尺寸像素已够密，直接画。

### 4. 描边的画布要留白

`add_outline` 向外扩的那一圈如果画布正好等于内容大小，会被边界裁掉——标志最外圈就没描边了。所以 `build_mark` 在描边时先给画布四周各留出描边宽度，再整体组建。

### 5. 毛玻璃底板：模糊背景 + 叠薄白，就地改在原图上

底板不是给水印加个半透明块，而是**把水印背后那块背景做高斯模糊、再叠一层半透明白**，最后圆角化并用高斯模糊做边缘淡出。看上去像一块磨砂亚克力，不遮挡太多。

一个必须保持的不变量：**模糊半径按比例算**，所以不同分辨率下模糊的「物理尺度」一致——预览看到的就是导出得到的。

### 6. 预览与导出走两条不同尺度的路

- 主预览：在缩略图（长边 ≤ 1100px）上合成水印，快
- 导出：在原图上合成，真
- 「查看原图」窗口：原图先降到 2200px 再合成，后台线程做，不阻塞主界面

因为所有尺寸都是比例，三条路出来的**观感一致**。实测水印区域平均像素差约 4/255。

**为什么查看原图要降到 2200**：在 4000 万像素的图上反复重绘，每次都要裁切 + 缩放上千万像素，`<Configure>` 一触发就是几秒。先把基图降到能用的大小，所有后续操作都在小图上做。

### 7. 预览的缩放用「视口裁剪」

放大时不把整张图放大，而是算出**当前可见的那一块**，只把这一块缩放到窗口尺寸画出来。所以放大 32 倍也不占额外内存、不因为图大而变慢。放大超过 1:1 用最近邻，能直接看到像素感。

### 8. 后台线程只通过队列与界面通信

「查看原图」的渲染在后台线程做，结果放进 `queue.Queue`，主线程定时轮询取出再建窗口。**不在子线程里碰 Tk**（`root.after` 跨线程是 Tkinter 的经典误用，会偶发崩）。

### 9. 配置：按文件夹 + 三层默认

`settings.json` 的结构是 `folders[文件夹路径] = {base, enh, enh_default, output_dir}`：
- `base`：常规参数（位置、大小、深浅适配、导出格式）
- `enh`：每张图单独的增强 `{文件名: {...}}`
- `enh_default`：本文件夹的增强默认

三层优先级的理由：多数图靠全局默认就够；一个文件夹通常有自己的一套脾气；个别图才需要单独调。

**两个必须守的规矩**（都踩过）：
- **切文件夹前先落盘**：保存是 700ms 防抖的，切文件夹时若还有待保存的回调，它会用新的 `self.folder`，把旧文件夹的数据写到新文件夹名下
- **关窗口前强制落盘**：否则最后一次改动（不到 700ms）直接丢

### 10. 面板宽度钉死

右侧参数栏放在固定宽度的容器里、锁定 grid 列宽、并让滚动条常驻。否则内容一变（某行出现/消失、滚动条开关），整栏宽度变化，控件会横向跳动。

### 11. 启动用 .bat，不双击 .pyw

部分机器上 `.pyw` 的系统关联指向 `C:\Windows\pyw.exe`（失效的旧 stub），双击无反应。`启动.bat` 用 `pythonw` 显式启动。`.bat` 内部**只能是 ASCII**（cmd 按系统代码页读批处理，UTF-8 的中文会解析错乱）。

## 日志与错误处理

- `store.log()` 记录启动、打开文件夹、导出、异常
- `_run()` 兜底：pythonw 没有控制台，异常会静默消失，所以捕获后写入 `启动错误.log`
- 日志超过 2MB 轮转成 `app.log.1`

## 可以放心改的地方

- 色彩常量集中在 `watermark.pyw` 顶部（`C_*`）
- 增强参数的默认值在 `ENH_DEFAULT`，改它会影响所有没单独设过的图
- 参数钳制在 `watermark_core.render()`（如 `outline_w` 上限 0.5），防止荒谬取值把程序拖死
