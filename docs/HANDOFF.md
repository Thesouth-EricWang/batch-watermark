## 二、已定案的决定

| 决定 | 结论 | 理由 |
| --- | --- | --- |
| 尺寸单位 | 一律用**比例**，锚在图片「较短边」；描边/底板各尺寸锚在「标志高度」 | 一批图分辨率、横竖、方向都不同，用绝对像素会让大图水印看不见、小图糊满 |
| 标志处理 | 拆成「校徽」+「文字」两个部件，深底只给校徽垫圆底、只把文字反白 | 校徽有具体图形和颜色，整块反白会毁掉它；文字是纯色块，反白最干净 |
| 标志组装分辨率 | **先缩到目标尺寸，再在其上做描边**（`build_mark(..., target_w, target_h)`） | 早期在 2760px 上描边再缩小：描边实际细近十倍、且每拖一格滑杆都要在上百万像素上跑膨胀 |
| 抗锯齿 | 小尺寸（长边 < 700px）组装时**超采样 2 倍**再缩回 | `ImageDraw` 画圆/描边不带抗锯齿，小尺寸下边缘会毛 |
| 描边画布 | 描边时给画布四周**留出描边宽度**再组装 | 否则外圈描边被画布边界裁掉（校徽圆、文字外缘没描边） |
| 毛玻璃底板 | = 背景高斯模糊 + 叠半透明白 + 圆角 + 边缘淡出；模糊半径按比例 | 比纯半透明块含蓄；按比例保证不同分辨率下「物理尺度」一致 |
| 预览/导出尺度 | 三条路不同尺度但比例一致：主预览用缩略图(≤1100px)、导出用原图、查看原图内部降到 2200px | 预览要快、导出要真；在几千万像素上反复重绘会卡死 |
| 预览缩放 | **视口裁剪**：只算可见那一块、缩放到窗口尺寸 | 放大 32 倍也不额外占内存、不因图大而变慢 |
| 后台线程 | 只往 `queue.Queue` 放结果，主线程轮询取出再动界面 | `root.after` 跨线程是 Tkinter 误用，会偶发崩 |
| 配置模型 | 按文件夹存 + **三层默认**（全局 → 本文件夹 → 本张） | 多数图靠全局够用；一个文件夹有自己脾气；个别图才单独调 |
| 保存时机 | 防抖 700ms；**切文件夹前先落盘、关窗口前强制落盘** | 防抖回调用的 `self.folder` 已变，会把旧数据写到新文件夹名下 |
| 右栏宽度 | 面板放进**固定宽度容器**并锁住 grid 列宽 | 否则内容一变整栏横向挪动（跳动） |
| 「水印黑白」控件 | 用**固定宽度按钮组**，不用 `CTkSegmentedButton` | 分段控件按内容自适应宽度，切换时会左右跳 |
| 顶栏菜单 | **界面内自绘**按钮 + 系统默认色下拉 | 系统菜单条由 Windows 绘制，`tk.Menu` 的配色染不到它，导致「顶栏没变色、下拉变色」 |
| 发布内容 | 仓库带**中性占位标志**；用户自备的 `logo.png` 进 `.gitignore` | 公开仓库不应带机构信息；工具本身通用 |
| 启动方式 | `启动.bat` 用 `pythonw` 显式启动 | 部分机器 `.pyw` 关联失效，双击没反应 |

## 三、已否决的方案

| 方案 | 为什么否 |
| --- | --- |
| **网页版（单文件 HTML）** | 用户觉得「要上传、不便」，大图处理也受限。已改成桌面版；旧的 `批量加水印.html` + `template` + `inject_logo.js` 保留在本地但已排除出仓库 |
| **放大时重新解码原图（追求清晰）** | 4K+ 图上明显卡顿。改为：放大只用缩略图（允许像素感），另开「查看原图」窗口看真实效果 |
| **在标志原始高分辨率上做描边** | 描边宽度错（细近十倍）+ 极慢。见上表「标志组装分辨率」 |
| **强制滚动条常驻**（改了 CTk 内部 `_scrollbar.grid(row=0,...)`） | 行号写错把滚动条顶到面板顶部，是真 bug；而且这一版 CTk 的滚动条本来就常驻，前提就是错的。已全部撤回 |
| **给 `tk.Menu` 自定义深色** | 只染到下拉、染不到系统菜单条，结果「顶栏没变、下拉变了」，与预期相反 |
| **`CTkSegmentedButton` 做「水印黑白」** | 宽度自适应导致切换时左右跳动 |
| **`root.after` 跨线程更新弹窗** | Tkinter 经典误用，测试环境直接报 `main thread is not in main loop` |
| **「查看原图」保持原图分辨率** | 5000 万像素图上每次重绘要裁切+缩放上千万像素，`<Configure>` 一触发就几秒。改为先降到 2200px |

## 八、环境与坑

- **`.pyw` 关联失效**：本机 `.pyw` 指向 `C:\Windows\pyw.exe`（旧 stub），双击无反应。一律用 `启动.bat`。
- **`.bat` 只能 ASCII**：cmd 按系统代码页（GBK）读批处理，UTF-8 中文会让命令解析错乱。
- **`ImageDraw` 不抗锯齿**：圆/描边边缘要自己超采样。
- **Tk 变量不能在后台线程读**（`main thread is not in main loop`）：先在主线程取值再传进线程。
- **`outline_w` 是比例不是像素**（0.08 = 标志高度的 8%）。传成 `8` 会让膨胀循环跑几百次直接卡死（核心已钳制到 0.5，但别依赖它）。
- **PowerShell `Set-Content`/`Out-File` 会按代码页转码**，破坏中文/emoji。改含非 ASCII 的文件用原生编辑工具或 Node/Python 直接写 UTF-8。
- **清理时不要删 `settings.json` 和 `logs/`**：那是程序的运行时数据，不是临时产物。
- **推送到 GitHub**：沙盒里 `git push` 需用
  `git -c credential.helper= -c http.sslBackend=openssl -c http.sslCAInfo="<HanaAgent>\resources\git\mingw64\etc\ssl\certs\ca-bundle.crt" push`，
  并用 `GIT_ASKPASS` 指向一个 `echo %GH_TOKEN%` 的 .bat 提供凭据（GCM 会弹窗失败）。
- 当前 token 权限：能建仓库、能改仓库属性，**现已可推送**（此前缺 Contents 写权限会 403）。
